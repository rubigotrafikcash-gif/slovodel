# Установка «СловоДела» — аккаунтный плагин и GitHub

Это руководство для стабильной версии 0.8.5. GitHub Release и аккаунтный плагин
имеют отдельный цикл обновления. Обновление GitHub не обновляет установленный
плагин автоматически: его пакет и версия проверяются отдельно. В 0.8.5 закреплён
[прямой резервный запуск Python](python-fallback.md) после ошибки инструмента
runtime или запрета PS1, без изменения политики исполнения и настроек Windows.

При проверке нового кандидата оставляй
один источник навыка: совпадающие описания старого плагина и кандидата создают
неоднозначность выбора. Проверяй каталог `skills/list` с принудительным обновлением
и фактический путь прочитанного SKILL.md. Отключение плагина через локальный
параметр не является доказательством отсутствия удалённого навыка в контексте.
Для изолированного теста можно отключить конкретную старую папку через
`skills.config` только на время запуска, не меняя общие настройки. Проверь
результат, а после теста удали временную установку штатно. См.
[параметры навыков](https://learn.chatgpt.com/docs/config-file/config-reference).

Локальный переключатель `plugins.<name@marketplace>.enabled` не отключает
аккаунтные или управляемые установки. Для автономного теста без подключённых
сервисов используй `-c features.apps=false` только в тестовом сеансе; оставь
локальный кандидат включённым и проверь его выбор по журналу. Это не проверка
обычного аккаунтного окружения со всеми интеграциями. Общие настройки пользователя
и идентификатор основного плагина ради теста менять не требуется.

**Одна папка `slovodel/` — полный автономный пакет навыка**: `SKILL.md`, `LICENSE`, `references/`, `assets/`, `scripts/`, `slovodel_core/`, `schemas/`. Python не нужен для качественной редактуры: AI-агент читает инструкции и оформляет текст. Для проверяемых числовых расчётов требуется **Python 3.10+** в среде агента и разрешение на локальный запуск скриптов.

## ChatGPT и Codex

Способ подключения зависит от среды. Сверено с [официальной документацией OpenAI](https://learn.chatgpt.com/docs/build-skills) 29 октября 2026 года.

| Среда | Подключение и вызов | Исполнение Python |
|---|---|---|
| Codex CLI / IDE / локальный Codex | Папка `.agents/skills/slovodel`; явный вызов `$slovodel` или выбор через `/skills` | Когда доступны файлы, интерпретатор и разрешение на исполнение |
| ChatGPT desktop с поддержкой отдельных навыков | Использовать доступный интерфейс Skills; явный выбор через `@` | Проверять возможности конкретной задачи |
| ChatGPT Chat / Work на web, desktop, mobile через плагин | Навык распространяется внутри установленного плагина; обновление GitHub само по себе не обновляет установленный пакет | Не предполагать доступ к локальному Python |

Репозиторий выпускает автономный каталог навыка. ZIP этой папки не является универсальным пакетом плагина для всех продуктов. Права аккаунта и реальный вызов модели проверяются отдельно; без Python доступна качественная работа по всей методологии.

Пути отдельных навыков и дополнительная поддерживаемая среда:
- [Codex — Build skills](https://learn.chatgpt.com/docs/build-skills): для пользователя `~/.agents/skills/slovodel/`, для проекта `<repo>/.agents/skills/slovodel/`; выбор навыка через `/skills` или `$slovodel`. Самостоятельный навык поддерживается Codex CLI/IDE/ChatGPT desktop; **не обещайте установку отдельной папки как полноценного ChatGPT mobile-плагина**.
- [Claude Code — Skills](https://code.claude.com/docs/en/skills): пользовательская директория `~/.claude/skills/slovodel/`, проектная `<repo>/.claude/skills/slovodel/`; явный вызов `/slovodel`. Не путать Claude Code с Claude web/синхронизацией аккаунта.

## Чистая установка из GitHub

Сначала скачай **конкретную опубликованную версию** в отдельную временную директорию. Для Linux/macOS (с установленным Git):

```bash
git clone --depth 1 --branch v0.8.5 https://github.com/rubigotrafikcash-gif/slovodel.git slovodel-release

# Установить в Codex (один раз, если такого каталога ещё нет):
mkdir -p "$HOME/.agents/skills"
cp -R slovodel-release/skills/slovodel "$HOME/.agents/skills/slovodel"

# ИЛИ установить в Claude Code:
mkdir -p "$HOME/.claude/skills"
cp -R slovodel-release/skills/slovodel "$HOME/.claude/skills/slovodel"
```

**Выбирай нужный агент; не обязательно устанавливать в оба.** Если каталог уже существует, **не накладывай новую папку поверх старой**: сначала сделай резервную копию старой версии и только потом обновляй. Перед первым использованием изучи `SKILL.md`, `LICENSE`, состав файлов и права стороннего словаря.

Для Windows PowerShell:

```powershell
git clone --depth 1 --branch v0.8.5 https://github.com/rubigotrafikcash-gif/slovodel.git slovodel-release

# Codex:
New-Item -ItemType Directory -Force "$HOME/.agents/skills" | Out-Null
Copy-Item -Recurse -LiteralPath "slovodel-release/skills/slovodel" -Destination "$HOME/.agents/skills/slovodel"

# ИЛИ Claude Code:
New-Item -ItemType Directory -Force "$HOME/.claude/skills" | Out-Null
Copy-Item -Recurse -LiteralPath "slovodel-release/skills/slovodel" -Destination "$HOME/.claude/skills/slovodel"
```

В PowerShell не выполняй `Copy-Item` поверх уже существующей папки без предварительного резервного копирования. Если нет Git, скачай **Source code (ZIP)** для конкретного GitHub Release, распакуй и скопируй только каталог `skills/slovodel` внутрь соответствующей директории агента, сохранив структуру. В графическом файловом менеджере путь и структура аналогичны.

**Удаление:** отключи/заверши работу агента и удали *только* установленную папку `~/.agents/skills/slovodel` или `~/.claude/skills/slovodel`, убедившись, что это именно пакет «СловоДел». Другие каталоги навыков не трогай. Встроенных сервисов/фоновых процессов и собственной БД нет.

## Проверка после установки

**С 0.8.4: выбор Python.** При доступном инструменте среды
`load_workspace_dependencies` агент сам получает полный путь Python, проверяет
его запуск и использует для `check_workflow.py`. Пользователь не должен
передавать путь вручную. Без такого инструмента в Windows есть автономный
`scripts/check_workflow.ps1`: он проверяет встроенный runtime и PATH, пропускает
WindowsApps и ограничивает пробу каждого кандидата пятью секундами. Настройки
Windows и политика PS1 не изменяются. Если PS1 запрещён, используй разрешённый
прямой запуск Python по пути, найденному в текущей среде. Код 8 — недоступный
интерпретатор; он не выдаётся за успешную проверку. См.
[подробный контракт запуска](agent-workflow.md#выбор-python-и-запуск-в-windows).

`execution.json` содержит `python_executable` и `python_version`. Это фактическая
среда запуска, а не версия модели. JSON Schema остаётся отдельной необязательной
проверкой: пакет `jsonschema` автоматически не устанавливается. Структура и
хеши проверяются и без него; отсутствие полной проверки обозначается явно.

При наличии локального Python и если установленный навык находится в Codex:

```bash
python "$HOME/.agents/skills/slovodel/scripts/workflow.py" --help
python "$HOME/.agents/skills/slovodel/scripts/analyze.py" --help
```

Для Claude Code замени путь на `$HOME/.claude/skills/slovodel`. В PowerShell используй `python "$HOME/.agents/skills/slovodel/scripts/workflow.py" --help` или `py -3` с доступным Python 3.10+.

**Windows и кодировки (с 0.8.0).** JSON в stdout всегда выводится в UTF-8, поэтому команды работают и в консоли с английской кодовой страницей. Входные файлы должны быть в UTF-8: в Windows PowerShell 5.1 `"текст" > file.txt` пишет UTF-16 и даст `INPUT_NOT_UTF8` — используй `Set-Content -Encoding utf8 file.txt` или файл, созданный агентом/редактором в UTF-8.

**Claude.ai (вкладка Customize → Skills).** Загрузи `slovodel-v0.8.5.zip` из GitHub Release целиком. Старая версия навыка в аккаунте не обновляется сама — удали её и загрузи новый архив, затем начни новый чат.

После запуска AI-агента проверь, что навык `slovodel` обнаружен, и отдельно проведи задания `audit`, `rewrite`, `create`, `compare` из [плана реальных агентских испытаний](https://github.com/rubigotrafikcash-gif/slovodel/blob/main/evals/cases.md). **Успешная проверка структуры файлов или CLI не равна проверке активации навыка реальным агентом.** Для Codex/Claude обязательно записывай фактическую версию клиента и сохранённый ответ; если агент не запускался — `NOT_RUN`.

## Без Python и без сети

**Наличие Python необязательно** для текстовой редакторской работы: даже без выполнения `scripts/*.py` агент использует `SKILL.md`, `references/` и `assets/`; разрешены только **качественные** выводы, без выдуманных баллов или заявления «Core запускался». Отсутствие локального Python в конкретной среде — не основание запускать внешние модели или передавать текст другому сервису.

Сами `scripts/*.py` используют **стандартную библиотеку Python**, без собственного API/сервера и без проектных сетевых вызовов. Среда исполнения по умолчанию **не имеет сетевой изоляции на уровне ОС**, поэтому не обещайте sandbox. Скачать GitHub-репозиторий или установить необязательные зависимости может потребоваться через интернет *до* использования офлайн-сценария.

## Что действительно проверено в CI

GitHub Actions на Linux, Windows и macOS ставит **копию одной папки** `skills/slovodel` в два временных дерева с путями Codex и Claude Code, убирает возможность использовать остальные файлы репозитория как импортируемые модули, запускает четыре режима Python из третьего каталога с `python -I`, проверяет JSON и `blocked` на разнице сумм, сводит версии внешних и встроенных схем. Проверка выполняется без реальных учётных данных. Это **подтверждённая проверка переносимости каталога и исполняемого слоя**, но **НЕ** запуск самих моделей Codex/Claude и не тест реального выбора навыка из меню, которые могут требовать установленный клиент и авторизацию.

Статус выпуска `v0.8.2` и проведённых проверок указан в заметках к нему; следи за [GitHub Release](https://github.com/rubigotrafikcash-gif/slovodel/releases). Не копируй в публичный репозиторий пользовательские исходники/скриншоты/токены.
