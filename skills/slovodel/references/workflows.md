# Сквозные сценарии

Читай этот файл, когда задача больше одного текста: серия, план, адаптация под каналы, целая страница или диалог. Общий процесс и проверки остаются из `SKILL.md`. Не задавай длинную серию вопросов, если безопасно обозначить допущение и заглушку. **Когда необходим сам исходник для `audit`/`rewrite`/`compare`, запроси его**, не имитируй анализ отсутствующего текста. При отсутствии ключевых фактов для готового к публикации текста обозначай статус черновика и конкретные подтверждения.

## Серия постов по одной теме

**Что нужно от автора:** тема, цель серии, число постов, канал, факты и материалы.

1. Раздели тему на 3–7 самостоятельных мыслей. Каждый пост должен быть понятен без остальных.
2. Для каждого поста определи одну мысль, крючок первой строки и одно действие.
3. Выбери порядок: от ситуации читателя к решению или от простого к сложному. Не используй «продолжение завтра» как приём удержания, если оно не нужно читателю.
4. Напиши посты и проведи общие проверки.

**Результат:** тексты постов и краткая таблица: номер, мысль, цель, действие. Предложи одну метрику для всей серии.

## План публикаций

**Что нужно от автора:** период, частота, площадки, цель, имеющиеся факты, события и материалы.

1. Сформулируй цель и 3–4 рубрики (например, польза, процесс, доказательства, диалог с читателем).
2. Расставь темы по календарю с учётом частоты и повода.
3. Для каждой темы дай рабочий заголовок и тезисы в одну-две строки.
4. Не придумывай акции, события, цены и даты: если их нет в данных автора, поставь `[укажите …]`.

**Результат:** таблица «дата, площадка, рубрика, тема, тезисы, действие». Если пользователь заказал план вместе с текстами, подготовь оба результата за один проход. Согласование промежуточного плана нужно только по его просьбе или при существенном незакрытом решении.

## Один текст для нескольких каналов

**Что нужно от автора:** исходный текст и список площадок.

1. Выдели ядро: главная мысль, проверяемые факты, желаемое действие.
2. Для каждого канала подбери длину и формат, первую строку и форму действия. Ограничения площадки сверяй с её актуальной документацией.
3. Сохраняй одни и те же факты во всех версиях. Меняй подачу, а не содержание.
4. Сравни версии между собой: цифры, названия и условия совпадают.

**Результат:** версия для каждого канала и строка о том, что осталось неизменным.

## Страница сайта или лендинг от брифа

**Что нужно от автора:** что предлагается, для кого, доказательства (цифры, примеры, отзывы с разрешением), основное действие, контакты.

1. Построй структуру по вопросам посетителя: что это, подходит ли мне, почему верить, сколько стоит, как начать, что если останутся вопросы.
2. Напиши заголовок и подзаголовок первого экрана и убедись, что они объясняют предложение сами.
3. Напиши тексты блоков, названия кнопок и микротексты форм.
4. Предложи пункты меню и подвал. Контактные и юридические блоки заполни только данными автора, остальное заглушки.

**Результат:** текст страницы по блокам и список того, что автору нужно подтвердить.

## Диалог бота

**Что нужно от автора:** цель бота, главные сценарии, что бот умеет и чего не умеет, когда подключается человек.

1. Составь карту сценариев: старт, ветки, завершение, передача человеку. Реплики пока не пиши.
2. Напиши реплики по карте: приветствие с вариантами ответа, короткие вопросы по одному, подтверждения.
3. Отдельно напиши реплики на непонимание, ошибки ввода и отказ. В каждой должен быть выход.
4. Пройди два-три сценария до конца, включая ошибочный ввод.

**Результат:** схема диалога и таблица реплик по шагам.

## Итоговая проверка

Перед выдачей выполни раздел «Подготовка и проверка текста» из `SKILL.md`. Выбирай подходящие операции из пяти уровней методологии, сохраняя общие факты во всех текстах. Для рекламных материалов, отзывов, чужих данных и обещаний прочти [проверки перед публикацией](compliance.md).

## Режимы при обработке нескольких текстов

- **Audit:** диагностика заданных материалов без переписывания и без готовых замен, если их не просили. Для отсутствующих текстов запроси исходники.
- **Rewrite:** улучшения по каждому исходнику с контролем чисел, отрицаний, ссылок и обещаний; объяснения — по контракту ответа SKILL.md, включая просьбу «только текст». При существенных незакрытых вопросах обозначь черновик.
- **Create:** создание из утверждённого брифа, отсутствие «Что изменено» без исходника; необходимые факты показывай заглушками.
- **Compare:** сравнение двух предоставленных версий, изменения фактов отмечай отдельно. Количественные разницы допустимы только при фактически выполненном совместимом измерении; иначе качественное сравнение без псевдоцифр.

Python Core реализован, но **не исполняется сам по себе**. При отсутствии реально доступного инструмента и разрешения остаётся качественный редакторский режим, не «скрытый» вычислительный fallback; историческая фоносемантическая программа по-прежнему не реализована.

## Реальный сквозной маршрут AI ↔ Core (Issue #8)

Все четыре режима и обязательные условия выполнения описаны в [agent-workflow.md](agent-workflow.md). Наличие Python в системе ещё не означает, что **он был запущен**: агент обязан реально создать локальные входные файлы, получить успешный код и проверить JSON. Исполняемое свидетельство не эквивалентно экспертизе редактора.

**Audit:** исходный текст → `workflow.py --mode audit --input original.txt` → числовые признаки (при наличии интерпретатора) → качественная диагностика, **без правки**.

**Rewrite:** исходник → AI-редактор применяет подходящие приёмы и составляет новую версию → один `workflow.py --mode rewrite --before original.txt --after revision.txt` → A8 и сравнение → выдача после смысловой сверки. Предварительный `audit` нужен только тогда, когда измерения оригинала влияют на план правки. `blocked` = **стоп для готовой к публикации версии**, код 5 не игнорировать. `draft_requires_review` требует ручной смысловой сверки.

**Create:** утверждённые факты брифа → AI создаёт черновик с нужными заглушками → `workflow.py --mode create --input draft.txt` → числовой анализ (если доступен) → только черновик, **без** самостоятельного подтверждения фактов и без «Что изменено».

**Compare:** две данные версии → `workflow.py --mode compare --before a.txt --after b.txt` → реальные дельты с совпадающими `method_id`, `method_version`, `dataset_id` → редакторское сравнение тона, смысла и отдельно найденных A8 расхождений. Без запроса не создавай новую редакцию.

**Fallback:** если Python недоступен, все четыре режима остаются **качественными редакторскими** (не исполнялись скрипты → нет числового отчёта). При необходимости юридической или денежной точности нельзя уверять пользователя, что отсутствие найденных нарушений гарантирует сохранение смысла.

Для серий постов и мультиканальных адаптаций запускай соответствующий `rewrite` для **каждой** изменённой версии относительно её реального исходника, не объединяй результаты разных текстов в один якобы исполненный прогон.
