# A8 — контроль защищённых фактов при переписывании

**Статус:** реализованный независимый офлайн-модуль публичного навыка Core 0.5.0. Это **детерминированный скрининг потенциальных расхождений**, а не доказательство смысловой эквивалентности. A8 **не измеряет** психологическое воздействие и не заменяет редактора, юридическую проверку или согласование публикации.

## Когда запускать

Для правки `rewrite`, перед предложением готового результата, передай **исходный и изменённый тексты** в разные локальные UTF-8 файлы:

```bash
python skills/slovodel/scripts/validate.py --before original.txt --after edited.txt
python skills/slovodel/scripts/validate.py --before original.txt --after edited.txt --output fact_report.json
```

Для критичных, но не формализованных требований составь текстовый `protected.txt` — **по одному точному выражению на строку** (не более 100 строк, после нормализации не длиннее 256 символов). Например: «согласование с редактором», «обязательное письменное согласие», название проекта. Для таких фраз включается отдельная проверка сохранности:

```bash
python skills/slovodel/scripts/validate.py --before original.txt --after edited.txt --protected-file protected.txt
```

Определение и разбор реальных условий остаются ответственностью автора/агента. **Не следует записывать личные секреты, пароли или токены** в списки и репозиторий. CLI не передаёт материалы через интернет и не изменяет исходные файлы.

## Что сравнивается

Текст приводится к Unicode NFC для проверки, но сами файлы не изменяются. По категориям строятся мультимножества защищённых значений; обнаруженные удаления **и добавления** блокируют результат. Повторяющиеся суммы считаются отдельно: если в тексте два раза `80 000 ₽`, удаление одного обнаруживается.

| Категория | Примеры | Ограничения |
|---|---|---|
| `url` | `https://example.org/a`, `www.example.org` | Не полный URL-парсер, пунктуация на конце эвристически исключается |
| `email` | `info@example.org` | Только распространённые формы адресов |
| `money` | `80 000 ₽`, `80 тыс. ₽`, `100 EUR` | Нормализуются разделители/масштаб, но не все способы записи сумм словами |
| `date`, `deadline` | `15.10.2026`, `15 октября`, `до пятницы` | Дата распознаётся лексически, **не вычисляется относительно календаря**; разные записи одной даты могут консервативно блокироваться |
| `range`, `quantity`, `number` | `от 5 до 7 дней`, `20 часов в неделю`, `10%`, `12` | Единицы сопоставляются только в поддерживаемых шаблонах; не понимает синонимы |
| `organization`, `person` | `ООО «Альфа»`, `Иван Иванов` | Узкие шаблоны; **не является полноценным NER**. Имена без полной формы могут быть пропущены |
| `condition` | `не`, `без`, `только`, `если`, `обязан`, `может`, `после` | Проверяются **формы слов**, не область действия отрицания или истинный смысл обязательства |
| `protected_term` | Ключевые формулировки из `--protected-file` | Поддерживаются точные фразы, без поиска синонимов и перефразирований |

**Приоритет:** URL, email, деньги, даты, сроки, диапазоны и количественные единицы извлекаются из копии по шаблонам, при последующих проверках использованные интервалы маскируются, чтобы не считать цифры внутри URL или суммы дважды. Смысловые ограничения остаются лексическими эвристиками; изменение смысла при совпадающих словах и числах может быть пропущено.

## Решения и безопасная обработка

- `blocked` — детерминированно найдено отличие в одной или нескольких защищённых категориях. Вывод **не считается готовым к публикации**; требуется ручная сверка и согласование затронутого факта/условия. Даже если правка намеренная, блокировка не снимается самим скриптом.
- `review_required` — тексты различаются, но поддерживаемые шаблоны не выявили расхождений. **Не означает** семантическую эквивалентность или безопасность; требуется редакторская проверка.
- `unchanged` — исходные строки точно одинаковы; оценка законности, правдивости и качества всё равно не проводилась.

Все состояния возвращают `publish_ready: false`, `semantic_equivalence: not_verified`. Скрипт **никогда сам не подтверждает публикацию**. Агент может сопровождать варианты редакторским анализом; ручное одобрение пользователь даёт отдельно в рамках своего рабочего процесса.

Коды выхода: `0` для `review_required`/`unchanged` с JSON, `5` для `blocked` **тоже с полным JSON**, `3` для неверного/недоступного входа или защищённых фраз, `4` для невозможности создать выходной файл, `2` при неверных аргументах CLI. Код `0` **не** является разрешением на публикацию.

## JSON-контракт и приватность

[schemas/fact-guard.schema.json](../schemas/fact-guard.schema.json) описывает **отдельный** от лингвистического отчёта формат:

```json
{
  "guard_version": "a8-rules-1.0",
  "tool_version": "0.5.0",
  "decision": "blocked",
  "publish_ready": false,
  "semantic_equivalence": "not_verified",
  "changed": true,
  "findings": [
    {
      "kind": "money",
      "severity": "blocker",
      "before_count": 1,
      "after_count": 1,
      "removed_count": 1,
      "added_count": 1
    }
  ],
  "warnings": ["HEURISTIC_ONLY_NO_SEMANTIC_EQUIVALENCE"],
  "source_sha256": "<sha256_of_original>",
  "revision_sha256": "<sha256_of_revision>",
  "protected_terms_count": 0
}
```

Это **иллюстрация формы**, не настоящий вывод запуска; реальный отчёт может содержать больше предупреждений и категорий. Суммы, ссылки, имена и защищённые строки в JSON **не публикуются** — только категории и счётчики. SHA-256 оригиналов и относительные частоты также могут раскрывать сведения об известных текстах, поэтому не публикуй приватные отчёты без проверки.

## Известные ограничения

1. Отсутствует контекстный семантический анализ, полноценное распознавание именованных сущностей и доказательство эквивалентности после перефразирования.
2. Не обнаруживаются все типы логических изменений: «не обязан» → «не запрещено» может сохранить счёт отрицаний, но полностью поменять смысл. Поэтому `review_required` не равен `approved`.
3. Выраженные словами числа, сложные денежные/процентные формулы, редкие валюты, переносы строк в составных условиях, скрытые Markdown-ссылки, нестандартные email/URL/имена могут не распознаваться.
4. Ложноположительная блокировка возможна при смене формата даты, корректировке орфографии в имени или изменении общего количества цифр; разблокировка требует **ручной** проверки.
5. Нет автоматического поиска критичных словосочетаний из смыслового брифа. Их нужно предоставить в `--protected-file`. Отсутствие найденных изменений не доказывает, что все факты сохранены.
6. Работа только с файлами до 1 МиБ, базовые ограничения на симлинки/перезапись остаются как в Issue #3. Никакой проверки договоров на соответствие законодательству.
7. В Issue #7 модуль вызывается **отдельной CLI-командой**. Полная интеграция с AI-редактором, подтверждением публикации и очередями — последующая Issue #8; до неё нельзя утверждать, что весь процесс уже автоматизирован.
