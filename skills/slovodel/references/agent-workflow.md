# AI Agent Skill × локальный Python Core — четыре редакторских режима (Issue #8)

Это **исполняемый публичный** workflow с Python 3.10+ внутри каталога `skills/slovodel`. Внешних AI API, серверов, сетевых запросов, автоматических публикаций и встроенного генератора прозы здесь нет. **AI-агент пишет/оценивает текст по SKILL.md**; Python анализирует подготовленные локальные файлы, проверяет защищённые факты и оформляет машинное свидетельство выполнения.

## Предусловия и порядок

### Выбор Python и запуск в Windows

Сначала используй путь Python, сообщённый средой, вместо голой команды `python`.
В PowerShell для автоматического поиска есть `scripts/check_workflow.ps1`.
Запускатель не требует уже запущенного Python. Он действительно исполняет короткую
пробу, проверяет Python 3.10+ и запускает тот же `check_workflow.py` с исходными
аргументами. Результат Core и его JSON не меняются.

Если среда предоставляет `load_workspace_dependencies`, получи путь Python из
этого инструмента, проверь `--version` и запускай `check_workflow.py` напрямую
полным путём. Путь определяет агент, не пользователь. Запускатель также принимает
`-Python <полный путь>` для проверки выбранного интерпретатора. Имя инструмента и наличие runtime зависят от среды, поэтому
это необязательная возможность. Пример без ручного пути, из папки навыка:

```powershell
& ./scripts/check_workflow.ps1 --mode rewrite --before original.txt --after revision.txt --output-dir check-1
```

Явный `-Python` или переменная текущего процесса `SLOVODEL_PYTHON` задают строгий
выбор: неработающий путь даёт ошибку 8, без тихой подмены. Иначе проверяются
стандартная локальная папка встроенного runtime OpenAI в профиле пользователя,
затем приложения `python`, `python3` и `py -3` из PATH. Папка runtime — резервная
эвристика, не официальный стабильный API. Ярлыки `Microsoft/WindowsApps`
пропускаются; каждая проба ограничена пятью секундами. Версия и фактический
исполняемый файл записываются в `execution.json`. Параметры workflow передаются
отдельными аргументами, включая пути с пробелами.

Код 8 означает отсутствие подходящего Python или ошибку его запуска, а не
успешное выполнение Core. Для этой ошибки отчёт Core не выдумывается. Код 5
от Core и код 7 проверки объёма передаются без повторного запуска. Установка
Python, изменение PATH, прав, execution policy и автоматическая установка
`jsonschema` не выполняются. Если политика запрещает PS1, уважай её: используй
разрешённый инструмент запуска с найденным Python или сообщи об ограничении.

В Linux/macOS получи доступный интерпретатор средствами текущей среды, проверь
его запуск и версию, затем вызывай `check_workflow.py` полным путём Python.
Не переноси Windows-путь на другую машину. При отсутствии исполняющей среды
остаётся качественная редактура с честным статусом измерений `unavailable`.

Сверено 30 октября 2026 года: [навыки в плагинах OpenAI](https://developers.openai.com/plugins/concepts/skills),
[упаковка плагина](https://developers.openai.com/plugins/build/plugins),
[границы hooks в Work](https://learn.chatgpt.com/docs/plugins).
Скрипты входят в пакет, но их наличие не создаёт исполнителя в каждом чате.
Hook не используется для исправления запуска Python. Плагин сохраняет
редакторскую работу без Python; делать весь плагин Desktop only ради Core
не требуется.

### Проверенный workflow

Для нового выполнения используй `scripts/check_workflow.py` с теми же входами,
что у `workflow.py`, и новым `--output-dir`. Он последовательно запускает Core
и единый валидатор; сохраняет `core.json`, `core.stderr.txt`, `verification.json`
и `execution.json` с реальным кодом процесса Core. Код оболочки PowerShell не
нужно принимать за код Core. Входы и существующий каталог не перезаписываются.
Старые команды ниже остаются интерфейсом отдельных шагов.

При ограничении объёма передай `--min-words` и/или `--max-words`; в audit/compare
также `--answer answer.txt`. В create проверяется `--input`, в rewrite — `--after`,
если иной `--answer` не указан. Считаются разделённые пробелами элементы с буквами
или цифрами; отдельное тире не слово. Код 7 требует исправить объём и выполнить
новый запуск на окончательном файле. Успех проверки объёма не доказывает точность.

Создание нового сокращённого поста по статье — create с проверкой обязательных
фактов агентом; rewrite предназначен для правки заданной редакции с сохранением
существенных фактов. Не выбирай режим ради получения удобного машинного статуса.
Исключение без Core относится к одной короткой строке; многофразовый абзац,
audit и compare при доступном Python проходят обычную проверку.

1. Определи режим по намерению автора: `audit`, `rewrite`, `create`, `compare`. `historical_research` остаётся источниковедческим; отдельно запрошенную арифметику Журавлёва с достаточными данными выполняет `scripts/zhuravlev.py`.
2. Если запрошен `audit`, `rewrite`, `compare`, убедись, что оригинал(ы) предоставлены. Для `create` нужен подтверждённый бриф. Сохраняй ключевые факты и ограничения, используй защищённые фразы при наличии.
3. **Проверь реальную возможность запускать локальный Python с доступом к файлам и разрешением автора/окружения.** Не запускай без подходящего инструмента, не выводи в ответе фиктивные логи. Работай во временной локальной директории с ограниченным доступом. Не записывай исходные тексты в GitHub, issue, лог действий или публичные комментарии.
4. Только если исполнение доступно, сохрани тексты в отдельных UTF-8 файлах (размер ≤1 МиБ каждый). **Не перезаписывай исходник**: изменённый текст лежит отдельно. Скрипт не создаёт `rewrite` или `create` самостоятельно.
5. Вызови `scripts/workflow.py` с нужным режимом и сохрани код завершения. Запусти `scripts/verify_workflow.py` на неизменённом JSON с теми же входными файлами: он проверяет исполнение, версию, входные SHA-256 и структурные условия; при доступном `jsonschema` — полные схемы. Не создавай собственный частичный JSON Schema-валидатор. Не показывай раздел «Измерено», если нет фактического успешного выполнения.
6. Отдели `reproducible` числовые метрики от редакторской **качественной** оценки. Для каждого использованного показателя бери прямо из отчёта `value`, `unit`, `method_id`, `method_version`, `dataset_id`, `n`; `unavailable/null` **не равно нулю**. Историческая «сила внушения», фоносемантические шкалы, прогноз поведения и конверсии недоступны.
7. `blocked` (код **5**, но с валидным JSON) — эвристическое расхождение, которое необходимо разобрать до выдачи готового результата. Исправь реальное непреднамеренное изменение факта и повтори Core. Если изменена лишь запись, сохрани корректную редакцию, исходный машинный статус и отдельно основание редакторского решения; не возвращай испорченное написание ради снятия блокировки. Неразрешённые расхождения оставь в черновике с конкретным вопросом. Находки `review` требуют смысловой сверки. `review_required` **тоже не является одобрением**. Никогда не объявляй `publication_ready=true`. Порядок и журнал решений — в [смысловой сверке](semantic-review.md).
8. Для работающего AI-навыка финальная редакторская сверка смысла, обещаний, контекста, разрешений/ссылок **остаётся обязательной**. Гарантий семантической эквивалентности/юридической пригодности алгоритм не даёт.
9. Удали временные локальные входные/выходные файлы в соответствии с правилами среды и требованиями пользователя; не объявляй удаления, если агент не выполнил его в действительности. Не копируй хеш/метаданные в публичное хранилище для конфиденциальных материалов.

## Команды и форматы (из корня репозитория; при отдельной установке запускай из каталога навыка)

```bash
# AUDIT: только диагноз, без новой версии
python skills/slovodel/scripts/workflow.py --mode audit --input original.txt

# REWRITE: AI сначала делает revision.txt; Core его НЕ создаёт
python skills/slovodel/scripts/workflow.py --mode rewrite --before original.txt --after revision.txt
# Для согласованных обязательных выражений:
python skills/slovodel/scripts/workflow.py --mode rewrite --before original.txt --after revision.txt --protected-file critical_terms.txt

# CREATE: AI создаёт draft.txt по брифу; Core проверяет только структурные признаки
python skills/slovodel/scripts/workflow.py --mode create --input draft.txt

# COMPARE: два предоставленных текста, сопоставимые метрики, отдельные различия фактов
python skills/slovodel/scripts/workflow.py --mode compare --before variant_a.txt --after variant_b.txt
```

Допускаются `--reference local_profile.json` (только добровольная ненормативная база A2), `--morphology` (только при отдельно установленном лицензированном словаре), `--output NEW_REPORT.json` (только новый файл). При отсутствии исходника аргументы дают код 2 или 3; нельзя симулировать выполнение без реальных файлов. **Код 5** обозначает `blocked` в `rewrite`; **0** не означает «публикация разрешена». В `compare` факт-скрининг показывает расхождения, но режим остаётся аналитическим и не блокирует просмотр версий.

## Таблица маршрутов

| Режим | Что создаёт AI-агент | Реальные шаги Core | Статус | Что отдавать пользователю |
|---|---|---|---|---|
| `audit` | Качественная диагностика **без** переписывания | `analyze_input` | `audit_only` | Диагностика, рекомендации; «Измерено» только по исполненному анализу |
| `rewrite` | Новую версию **после** анализа оригинала | `analyze_original → check_agent_edit_facts → analyze_agent_revision → compare_reproducible_metrics` | `blocked` либо `draft_requires_review` | Текст/черновик, необходимые подтверждения; объяснение правок — по запросу и контракту SKILL.md |
| `create` | Черновик из брифа | `analyze_agent_draft` | `draft_requires_review` | Черновик/текст и пробелы брифа, **без** «Что изменено» |
| `compare` | Качественное сопоставление двух заданных версий | `analyze_first → analyze_second → compare_reproducible_metrics → screen_fact_differences` | `comparison_only` | Различия по смыслу, фактам и замеренным метрикам, не третью редакцию |

В `rewrite` шаг «AI редактирует» **происходит снаружи** исполняемого Python workflow, между предварительным анализом и A8, поэтому `steps_executed` содержит только реально выполненные **Core** шаги. Это не означает, что Python умеет писать текст. Отдельный `--mode audit` перед правкой нужен, только если метрики оригинала нужны для плана редактуры; иначе достаточно одного `--mode rewrite`, а отдельный `validate.py` не запускается (A8 уже внутри). Нельзя утверждать, что вызов автоматически направляет AI.

## JSON-вывод

Формат [workflow.schema.json](../schemas/workflow.schema.json) — верхнеуровневый пакет `mode`, `execution`, `ai_text_generation`, `publication_ready=false`, `decision`, `steps_executed`, `pre_analysis`, `post_analysis`, `comparison`, `fact_guard`, `warnings`. Вложенные отчёты принадлежат ранее внедрённым `analysis.schema.json`, `compare.schema.json`, `fact-guard.schema.json`; последовательно проверяй **все четыре** при доступном JSON Schema-валидаторе. Объём метрик может быть большим, поэтому пересказывай только непосредственно значимые для конкретного текста.

`fact_guard` не копирует суммы, имена, ссылки: лишь категории и счётчики. Измеренные метрики содержат агрегаты, версии и предупреждения. Не вставляй в ответ внутренние системные хеши или приватные данные без необходимости.

## Единый помощник проверки свидетельств (0.8.3)

```text
python scripts/workflow.py --mode rewrite --before original.txt --after revision.txt --output core.json
# Сохрани реальный код завершения предыдущего процесса (0 или 5).
python scripts/verify_workflow.py --report core.json --before original.txt --after revision.txt --core-exit-code 0 --output verification.json
```

Для audit/create передавай `--input`. Если Core использовал `--context-file`,
передай тот же файл помощнику. Код 5 у rewrite с `blocked` — допустимое
машинное свидетельство; передай именно 5. Успех помощника означает целостность
свидетельства, не разрешение на публикацию. Помощник не переписывает Core JSON.
Повторный `--output` не перезаписывает существующий файл. Код ошибки помощника — 6.

`schema_validation=passed` означает полную Draft 2020-12 валидацию всех
непустых компонентов; `unavailable` означает отсутствие пакета `jsonschema`.
Структурная проверка и хеши выполняются в обоих случаях. Для обязательной полной
проверки используй `--require-schema`: при недоступности валидатора будет ошибка,
а не вымышленный PASS. Устанавливать зависимости для обычной редактуры не нужно.
`semantic_review=not_performed_by_verifier` требует последующей сверки агентом.

## Fallback без Python

Когда среда не может запускать скрипты/не получила разрешения:
- Не утверждай, что Core запускался, не придумывай `reproducible`-числа и не изображай JSON-отчёт.
- Выполни вручную **только качественный** `audit`/редактуру/`create`/сопоставление. Для `rewrite` самостоятельно перечисли сохранённые цифры, URL и условия **только как редакторскую сверку**, отметь, что автоматическая A8-проверка не проведена; при юридически значимом/критическом тексте не выдавай неподтверждённую редакцию за безопасную.
- `compare` без исполняемой среды: сравни тон, смысл и исходные факты, но **не вычисляй воображаемые проценты влияния или технические показатели**.
- Если пользователь просил именно вычислительный отчёт, честно укажи, что выполнение недоступно.

## Что НЕ реализовано

Нет автономного AI-генератора, AI-API, подключённого приватного MCP, Notion/Telegram, автоматической публикации, полноценного семантического доказательства сохранения фактов. **E2E-тесты Issue #8 проверяют фактическое исполнение локального Core и структурные статусы**, а не объективное качество созданного AI текста или реальный запуск чужого агента без доступа к его окружению.

## Контекстные добавления в 0.8.2

Для rewrite/compare доступен `--context-file context.json`. Формат и границы —
в [смысловой сверке](semantic-review.md). Составляй записи из исходного брифа
и метаданных до оценки результата, с указателем на источник. Не включай в
подтверждения собственные догадки. `fact_guard` сохраняет исходную диагностику;
`context_review` отдельно объясняет поддержанные добавления и остаточные блокировки.
Даже при снятии workflow-блокировки обязательна редакторская проверка.

## Завершение работы агентом

После Core агент сам выполняет смысловую сверку итогового результата. Сопоставь
не только короткий фрагмент, но и бриф, заголовок источника и весь переданный
список защищённых утверждений. Для audit проверяй основания замечаний, для
самостоятельной устной версии — наличие предмета речи и ясные отсылки.
Исправь найденное и повтори Core на окончательной версии. Не отправляй задачу
пользователю как незавершённую только потому, что Core требует review.

В исследовании или журналируемой проверке храни отдельно от неизменённого JSON
Core: источник утверждения, точный поддерживающий фрагмент результата, решение,
обоснование, исправления и хеш окончательного текста. Редакторское решение агента
не является независимой человеческой оценкой или проверкой актуальности источника.
Не меняй `publication_ready=false` и не дописывай в Core вымышленные измерения.
В обычной выдаче достаточно текста и только существенных неразрешённых вопросов;
внутренний журнал и статусы не нужно показывать без запроса.
