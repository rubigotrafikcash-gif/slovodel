# A5 — отключаемый морфологический POS-анализ

Состояние: Python Core **0.4.0**. Движок строго **необязателен** и включается только аргументом `--morphology`. По умолчанию морфологические значения не считаются: `pos_distribution = unavailable/null` с причиной `MORPHOLOGY_OPT_IN_REQUIRED`; всё остальное работает без внешних пакетов.

## Запуск

```bash
# необязательная отдельная установка (для Python 3.10+)
python -m pip install pymorphy3==2.0.6 pymorphy3-dicts-ru==2.4.417150.4580142

python skills/slovodel/scripts/analyze.py --input text.txt --morphology
python skills/slovodel/scripts/compare.py --before old.txt --after new.txt --morphology

# без пакетов/флага — базовые метрики продолжают работать
python skills/slovodel/scripts/analyze.py --input text.txt
```

Данные не отправляются на сервер и не загружаются при запуске; только локальный словарь из отдельно установленного пакета. Если пакетов нет: `MORPHOLOGY_DEPENDENCY_NOT_INSTALLED`; версия не поддерживается: `MORPHOLOGY_VERSION_UNSUPPORTED`; библиотека не инициализировалась: `MORPHOLOGY_BACKEND_UNAVAILABLE`. Результат CLI остаётся успешным JSON **с предупреждением и unavailable**, а не частичным выдуманным подсчётом POS.

## Алгоритм

1. То же `NFC`, маскирование URL/email, `casefold` и буквенная токенизация, что и A1; выбрать **только русские токены**. Обработку тире/дефисов см. `metrics-contract.md`. Слова, имена собственные и некнижные формы могут получать множественные варианты.
2. Получить список вариантов из `pymorphy3.MorphAnalyzer.parse(word)` **без контекстного разрешения**. Учитываются только варианты с `is_known=True`, то есть присутствующие в словаре. Прогнозирующие эвристики для отсутствующих слов не объявляются известными.
3. Если нет известных вариантов — `OOV`; если отсутствуют разборы, нераспознанные категории, или `POS=None` — `UNCLASSIFIED`. Если среди известных вариантов найдено **несколько разных POS** — `AMBIGUOUS` и токен исключается из счётчиков частей речи. Несколько падежей/чисел с **одним POS** не считается неоднозначностью части речи.
4. Если только один POS среди известных вариантов — он входит в соответствующий счётчик. Возвращаем агрегаты без исходных слов, словарных форм, лемм и имен людей.
5. Классы: `NOUN, ADJF, ADJS, COMP, VERB, INFN, PRTF, PRTS, GRND, NUMR, ADVB, NPRO, PRED, PREP, CONJ, PRCL, INTJ` (17). Для каждого POS: `pos_<tag>_count` и `pos_<tag>_share` (доля от **всех русских токенов**, а не только распознанных).
6. Дополнительные счётчики `pos_ambiguous_token_count`, `pos_oov_token_count`, `pos_unclassified_token_count`, `pos_resolved_token_count`; качество покрытия `pos_coverage_ratio = resolved / russian_token_count`. Сумма 17 классов, AMBIGUOUS, OOV, UNCLASSIFIED **точно равна** количеству русских токенов (A1).
7. Когда русских токенов нет, счётчики равны **0**, а все доли и coverage = `unavailable/null` (делить не на что).
8. Для выданных значений `status=reproducible`, метод `slovodel.a5.pymorphy3.unique_pos`, версия метода Core **0.4.0**, `dataset_id=pymorphy3:2.0.6|pymorphy3-dicts-ru:2.4.417150.4580142`, предупреждения `NO_CONTEXT_DISAMBIGUATION`, `POS_DICTIONARY_CC_BY_SA`, `POS_IS_NOT_PSYCHOLOGICAL_INFERENCE`.

**Важное ограничение:** распределение показывает долю лексем, для которых словарь возвращает однозначную **часть речи без учёта контекста**. Это не точная синтаксическая разметка предложений, не мнение об авторе, его эмоциях или достоверности. POS по некоторым словам, именам, дефисным/разговорным конструкциям может не определяться. Ничего не «угадываем», чтобы заполнить 100%.

## Сравнение двух текстов

`compare` использует **одну загруженную версию** библиотеки/словаря для обоих текстов. Дельты доступны только при совпадении `method_id`, `method_version`, `dataset_id`. Для `compare(x,x)` все рассчитанные дельты = 0. Доли POS различной длины математически сравнимы, однако для малых текстов и неполного покрытия **не являются показателем улучшения качества**.

## Лицензии, безопасность, проверка

См. [morphology-licenses.md](morphology-licenses.md). В `MIT`-репозиторий **не включены словарь или код стороннего анализатора**. Реальный пакет ставится отдельно; код не запускает `pip`, не скачивает корпус и не публикует словоформы. Данные текста остаются локальными, а содержимое не попадает в отчёт; SHA-256 и POS-агрегаты всё равно могут быть чувствительны.

В `CI`: сначала тесты без необязательной зависимости, затем полный прогон со схемами JSON и наконец ещё один прогон после установки конкретных версий `pymorphy3`/`dicts`. Проверяются реальные слова, неоднозначность, OOV, короткие/пустые тексты и отсутствие утечки в JSON.
