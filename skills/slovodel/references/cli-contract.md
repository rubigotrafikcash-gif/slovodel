# CLI публичного «СловоДела» — исполняемый контракт

**Статус:** офлайн Python Core `0.8.2`: A1/A3/A4/A6/A7 и редакторские A4/A7/A9 (метод 0.8.0, без изменений), опциональное A2, **необязательный POS-анализ A5** по отдельно установленным `pymorphy3` и русскому словарю, проверка защищённых фактов A8 (rules 2.2) и экспериментальная арифметика Журавлёва на данных пользователя. Без флага `--morphology` данные POS не рассчитываются. JSON schema `1.0.0`; схема A8 обновлена под версию правил 2.2, сигналы контекста и журнал нормализации. Метод и инструмент версионируются независимо; `dataset_id=null` допустим для вычисления без внешней базы. Это независимый публичный инструмент, не оригинальная программа «Словодел»/«Диатон».

## Требования

- Python **3.10 или новее**, только стандартная библиотека в момент исполнения.
- Нет собственного сервера, API, ключей, n8n или подключения к сети.
- Вход: **существующий обычный UTF-8 файл**, максимально 1 048 576 байт (1 MiB), включая пустые файлы; BOM допускается и учитывается при хешировании.
- Символические ссылки на входной файл отклоняются; FIFO и устройства — тоже. Ограничение: в этой версии не обеспечена защита от ссылок в **родительских каталогах** и не изолируется окружающая файловая система; агент должен запускать код в доверенном локальном окружении.
- Вывод по умолчанию в stdout **всегда в UTF-8**, независимо от кодовой страницы консоли (с 0.8.0), либо в **новый** файл через `--output`, создаваемый эксклюзивно (старые файлы никогда не перезаписываются), права 0600 на POSIX. Имена путей и содержимое текста не включаются в сообщения об ошибке.

## Команды

```bash
python skills/slovodel/scripts/analyze.py --input input.txt --mode audit --format json
python skills/slovodel/scripts/analyze.py --input input.txt --output audit.json
python skills/slovodel/scripts/compare.py --before before.txt --after after.txt --output comparison.json
python -m unittest discover -s tests -v
```

Запускать из каталога репозитория или по абсолютным путям. После копирования каталога `skills/slovodel` команды доступны внутри этого каталога: `python scripts/analyze.py ...` и `python scripts/compare.py ...`. Пакет `slovodel_core/` расположен **внутри навыка** — внешняя установка через `pip` не требуется. При желании проект можно упаковать через корневой `pyproject.toml`, но установка пакета необязательна.

## Что действительно работает

- Валидация входного файла и строгое декодирование UTF-8.
- SHA-256 **оригинальных байтов**, без изменения файла.
- Подготовка **копии в памяти** с Unicode NFC и флагом, изменилась ли строка; карта смещений между исходником и NFC **ещё не реализована**.
- Детерминированные `audit` и `compare` с версионными JSON-отчётами и измеренными орфографическими показателями.
- Доступны A1: русские буквы (включая `е/ё`), токены, предложения (эвристика), приблизительные графемоподобные кластеры; A3: буквенные n-граммы и окна повторов; A4: количество гласных в русских словах; A6: агрегаты русских словоформ; A7: формальное композиционное сечение.
- Описание каждой единицы/формулы, исключений, нормализации и ограничений: [metrics-contract.md](metrics-contract.md).
- Всё, что не реализовано и не подтверждено, остаётся `unavailable` с `value: null`. Исторический статус — `historical_compatibility = not_verified`.

**Что не работает:** фонемная транскрипция, ударения, оценка звукового символизма по встроенным таблицам, **контекстно подтверждённая POS-разметка**, **лицензированная и подтверждённая общерусская норма** для A2, исторические расчёты «Диатона»/Черепановой и AI-редактура из Python. Формула Журавлёва доступна только как экспериментальная арифметика на оценках пользователя (`scripts/zhuravlev.py`), без таблиц звукобукв. Локальное сравнение A2 — не нормативное; по умолчанию `norm_letter_deviation` остаётся `unavailable/null`. Нельзя утверждать, что эти расчёты выполнены. В `compare` возвращаются числовые дельты только по фактически реализованным сопоставимым показателям; `comparison_status: completed` не означает исторического или полного лингвистического анализа. Для `compare(x,x)` все сопоставимые дельты равны нулю; разнодлинные русские тексты не сравниваются по TTR, так как показатель зависит от числа слов.

## Опциональный A2

Дополнительно доступен `scripts/build_reference.py`: строит локальный профиль частот без исходного текста, с пользовательским описанием источника, версии, лицензии и основания прав. При `analyze.py --reference profile.json` и `compare.py --reference profile.json` рассчитываются отдельные `local_ref_*` дельты и отношения; ни один источник не загружается из сети. Условия: [a2-contract.md](a2-contract.md), формат: [local-reference.schema.json](../schemas/local-reference.schema.json). Такие данные не считаются нормативными; `norm_letter_deviation` по умолчанию и с профилем недоступен.

## Опциональный A5

CLI `analyze.py` и `compare.py` принимают флаг `--morphology`. Он **не** устанавливает зависимости: нужна отдельная локальная установка `pymorphy3==2.0.6` и `pymorphy3-dicts-ru==2.4.417150.4580142`. Если пакет отсутствует/не совпадает версия, используется `pos_distribution=unavailable/null` с диагностическим кодом, но базовые измерения продолжаются. При наличии корректного словаря появляются `pos_<tag>_count/share`, неоднозначность/OOV и показатель доли распознанных токенов. Это не контекстный POS-tagging. Подробности: [morphology-contract.md](morphology-contract.md), [morphology-licenses.md](morphology-licenses.md).

## A8 — отдельный независимый отчёт защищённых фактов

`scripts/validate.py --before old.txt --after new.txt` сравнивает URL, email, деньги, даты, дедлайны, числовые диапазоны, количественные единицы, имена в ограниченных шаблонах, модальные и отрицательные слова. Необязательный `--protected-file important.txt` — один обязательный термин/фраза на строку. Формируется отдельный JSON по `schemas/fact-guard.schema.json` со статусами `blocked`, `review_required`, `unchanged`, всегда `publish_ready=false`. В отличие от `compare.py`, это **не числовой отчёт качества текста**. Изменение защищённых данных → код выхода `5`, JSON при этом записывается. Семантическая эквивалентность **не удостоверяется**. Подробнее [fact-guard-contract.md](fact-guard-contract.md).

## Формат и отслеживаемость

- `schemas/analysis.schema.json`, `schemas/compare.schema.json` — **публичные JSON Schema Draft 2020-12**.
- Поля аудита: `schema_version`, `tool_version`, `mode`, `language` (целевой русский, **определение языка не выполняется**), `language_detection`, `source_sha256`, `source` (хеш, байты, NFC), `source_policy`, `measurements`, `historical_compatibility`, `warnings`, `errors`.
- Поля сравнения: те же общие метаданные, `before`, `after`, `measurement_method_version`, `comparison_status`, `comparisons` — числовые пары `before`, `after`, `delta=after-before`, `n_before`, `n_after`, единицы, метод, версия, предупреждения.
- Метрика: `id`, `value`, `unit`, `status`, `method_id`, `method_version`, `dataset_id`, `n`, `warnings`. Реализованные значения имеют `status=reproducible`, версию метода и число; недоступные имеют `status=unavailable`, `value=null`.
- Исходные тексты **не включаются** в отчёт. Из отчёта можно узнать размер и SHA-256; хеш может раскрыть соответствие известному тексту, поэтому не публикуйте отчёты конфиденциальных материалов без согласования.
- Отчёт не сохраняется на диск автоматически: только при явном `--output`. Обычный stdout может сохраняться самой агентской средой — необходимо учитывать её правила.

## Коды выхода

| Код | Значение |
| --- | --- |
| 0 | Успех, создан отчёт |
| 2 | Ошибка параметров CLI (`argparse`) |
| 3 | Некорректный/недоступный вход |
| 4 | Ошибка записи результата, включая существующий выходной файл |
| 5 | Команда `validate.py`: обнаружено изменение защищённых фактов (`blocked`), полный JSON-отчёт при этом сохраняется |

Стандартный stderr содержит только фиксированный `SLOVODEL_ERROR: <КОД>`, никаких фрагментов текста. Исключение: argparse может показать недопустимое **значение аргумента** (например, неверное `--mode`); не передавайте содержимое текста в CLI-аргументах.

## Тесты

`tests/test_cli.py` и `tests/test_metrics.py` используют стандартный `unittest`. Проверяются исходные байты, детерминизм, граничные файлы, Unicode, дефисы, URL/email, русские буквы, повторы, слоги, словоформы, сечение, сравнение одинаковых/разнодлинных текстов. При наличии необязательного пакета `jsonschema` дополнительно валидируются схемы Draft 2020-12. Успешность реальных запусков см. в протоколе Issue #4 в GitHub; существование тестов само по себе не означает их прохождения.

## Ограничения безопасности

Нет сетевых библиотек/сетевых вызовов в коде, но локальный Python-процесс по умолчанию не помещён в сетевой sandbox ОС. Не запускайте недоверенные модули и не выдавайте обещание защиты от внешних Python-hook/окружения. Значение `network_access: false` означает, что **данный код не инициирует сетевые запросы**, а не гарантию отсутствия сетевого доступа у интерпретатора.

## Экспериментально: арифметика Журавлёва (0.8.0)

```bash
python skills/slovodel/scripts/zhuravlev.py --input elements.json
```

`elements.json` содержит **ровно одно** из полей: `elements` (список `{score 1..5, frequency > 0, first, stressed}` — взвешенная оценка), `scores` (простое среднее) или `counts` (распределение ответов 1..5). Оценки и частоты дает пользователь; таблиц в пакете нет. Вывод — [zhuravlev-experimental.schema.json](../schemas/zhuravlev-experimental.schema.json), всегда `status: experimental` и предупреждение `NOT_DIATON_NOT_HISTORICAL_PROGRAM_OUTPUT`. Ошибки — фиксированные коды (`SCORE_OUT_OF_RANGE`, `FREQUENCY_NOT_POSITIVE`, `MORE_THAN_ONE_FIRST_ELEMENT`…), код выхода 3. Это не оценка рекламного текста.
