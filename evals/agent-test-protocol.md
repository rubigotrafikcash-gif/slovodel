# Протокол проверки поведения AI-агента (Issue #9)

Цель — не подменять **проверку работающего AI-агента** результатами Python unit/E2E. Испытание навыка требует отдельной сессии, где установлен конкретный каталог `skills/slovodel`, известна редакция Git commit, разрешены/запрещены локальные скрипты, а агенту направляют заранее зафиксированный синтетический запрос.

## Четыре независимые категории результатов

| Слой | Что действительно проверяется | Как отмечать |
|---|---|---|
| Core unit/E2E CI | Детерминированные метрики A1–A8, режимы и ошибок, JSON Schema, CLI | `PASS`/ `FAIL` по GitHub Actions и машиночитаемым артефактам, без выводов о поведении LLM |
| No-network smoke | Четыре режима на тестовом тексте при запрете стандартных вызовов sockets/urllib, статический анализ импортов | `PASS`/ `FAIL` с оговоркой: **не песочница ОС** |
| GPT-6 in-session manual rehearsal | Текущий ассистент читает `SKILL.md` из GitHub **как инструкцию**, формулирует ответы на искусственные запросы и вручную оценивает соответствие | `SELF_REVIEW_PASS` / `SELF_REVIEW_FAIL`, артефакт с дословным ответом; это **не** внешнее приложение с установленным навыком |
| Independent installed-agent E2E | Codex, Claude Code, Gemini CLI или отдельная сессия с *фактически установленным навыком*, слепой оценкой и логами разрешённого локального Python | `PASS` / `FAIL` только при подтверждённом запуске; иначе `NOT_RUN` |

## Репетиция в текущей сессии

Дата: **15.10.2026**, модель **GPT-6**. Базовый навык: `skills/slovodel/SKILL.md` + справочники из `main` после Issue #8 (commit `20a5960d6fb17ee708233b153dabc547f1c47275`). Автор ответов и рецензент — **один и тот же ассистент**, поэтому отсутствует независимость оценки.

[18 реальных текстовых ответов GPT-6 из текущей сессии](agent-runs/2026-10-15-gpt6-in-session.md) зафиксированы без реальных пользовательских данных. Они построены на синтетических запросах `evals/cases.md` и в явном качественном режиме **без Python**. Все 18 получили авторскую самооценку `SELF_REVIEW_PASS`; итог для независимых клиентов и плагинов — **NOT_RUN**, не 18/18 PASS. Дата, точный контекст, источник и ограничения указаны в самом артефакте.

## Воспроизводимый независимый прогон

1. Возьми ровно commit из тестируемого PR/релиза, запиши SHA, имя и версию агента, конфигурацию и поддерживаемый путь установки skill.
2. Установи каталог `skills/slovodel` целиком (включая Python Core/scripts/references) по документации своего агента. Не бери секреты, приватные посты или пользовательские материалы.
3. Открой **новую** сессию без предыдущих ответов, предъяви синтетический запрос из [cases.md](cases.md) (включая недопустимые гарантии, исторические баллы, фактологические изменения, отсутствие исходника).
4. Для каждого запроса сохрани **дословный ответ**, конфигурацию инструментов, реальный статус локального Python и фактические CLI-логи/JSON только если запускаемый инструмент действительно вызван. Сокрытие текста логами без прогона считается `FAIL`.
5. Независимый рецензент проверяет отдельные критерии `[ ]`, оценивает `PASS/FAIL` с объяснением, приложением обезличенного ответа и ссылкой на точный commit. Случай без запуска — строго `NOT_RUN`.
6. Для `rewrite` с изменением суммы, срока или отрицания строго требуй явную остановку публикации/подтверждение. Для `audit` — отсутствие скрытой редакции. Для `compare` — только реально воспроизводимые числа. Для `create` — только подтверждённые факты брифа.
7. Не загружай наружу конфиденциальную переписку, токены, исходные тексты клиентов и приватные отчёты. Публичный журнал должен содержать только тестовые примеры.

### Рекомендуемый шаблон журнала (каждая попытка)

```text
test_id: A01
agent: Codex CLI (пример; указать фактическую версию)
skill_commit: <full SHA>
date_utc: <YYYY-MM-DDTHH:mm:ssZ>
execution: installed_agent | in_session_manual | core_only
python_available: true | false
python_invocations_verified: []   # только реальные команды
expected_behavior: <из cases.md>
observed_response: <обезличенный дословный ответ>
evaluator: <независимый проверяющий, если есть>
result: PASS | FAIL | NOT_RUN | SELF_REVIEW_PASS | SELF_REVIEW_FAIL
reason: <проверяемая причина>
```

## Критерий выпуска

Машинный CI и coverage **не заменяют независимый агентский тест**. Если требование релиза предполагает испытания в Codex/Claude/Gemini, текущий PR лишь подготавливает методы и тестовые материалы; **нельзя** объявлять подтверждённую переносимость по результатам репетиции текущим GPT-6. Для окончательного публичного релиза нужен отдельный запуск установленного навыка в выбранных клиентах и оценка без самооценки автора.

Общие ограничения: анализатор не воспроизводит «Диатон», локальные частоты A2 не нормативны, A8 — эвристический fact guard, `publication_ready=false` не отменяется даже при зелёном CI.
