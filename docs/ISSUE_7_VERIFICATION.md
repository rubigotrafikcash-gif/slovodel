# Issue #7 — акт реализации и проверки A8 fact guard

Дата: **15 октября 2026 года**. Область: исключительно публичный Agent Skill «СловоДел»; никаких изменений приватных MCP/API/VPS/n8n, сервисов Wirebot или соседних задач. PR [#17](https://github.com/rubigotrafikcash-gif/slovodel/pull/17).

## 1. Что реализовано

- [slovodel_core/fact_guard.py](../skills/slovodel/slovodel_core/fact_guard.py) — воспроизводимая **эвристическая проверка риска изменений** A8, версия правил `a8-rules-1.0`. Это **не** математическая оценка качества текста и не доказательство семантической идентичности.
- Отдельная команда [scripts/validate.py](../skills/slovodel/scripts/validate.py) принимает обязательные `--before` и `--after` (локальные UTF-8 файлы, ограничения ядра ≤1 МиБ), необязательный `--protected-file` с до 100 критическими фразами и `--output` для нового JSON-файла.
- [JSON schema fact-guard](../schemas/fact-guard.schema.json): `decision` = `blocked|review_required|unchanged`, `publish_ready=false` в любом случае, `semantic_equivalence=not_verified`. Подсчёты различий по категориям без вывода исходных сумм, имён или URL.
- Категории: URL, email, деньги, даты, относительные дедлайны, диапазоны, числовые величины с единицами, отдельные числа, названия организаций в узком шаблоне, некоторые полные ФИО, обязательные/модальные слова и фразы из `--protected-file`.
- Изменение **любого найденного защищённого значения**, в том числе замена при одинаковом числе элементов или добавление нового, → `blocked` + код возврата **5**, при этом полноценный JSON сохраняется. Случаи неопознанной смысловой замены → **не более чем** `review_required`, обязательна ручная проверка.
- Исходные файлы не переписываются, конфиденциальный текст/словарные ключи не публикуются в отчёт; учитывается, что SHA-256 и агрегаты также могут являться чувствительными метаданными.
- Контракт `audit`/`compare` метрик A1–A7 не менялся: fact guard вынесен отдельно, его вызов в `SKILL.md` до готовой публикационной версии предписан только при реально доступном разрешённом локальном Python. Полная автоматическая цепочка редакторской интеграции отложена до Issue #8.
- [Точный договор A8](../skills/slovodel/references/fact-guard-contract.md), [обновлённый README](../README.md), [CLI-документ](../skills/slovodel/references/cli-contract.md). Python Core **0.5.0**, версия отчёта fact guard независима от прежних JSON Schema.

## 3. Границы применимости, известные риски

1. **Никакой гарантии 100% семантической эквивалентности.** Поддерживаются ограниченные регулярные выражения и точные пользовательские фразы. Семантическая потеря/смена области отрицания, синонимы или новый юридический смысл могут пройти как `review_required`.
2. Узкие детекторы имени и организации — не NER. Даты сравниваются консервативно по форме, даже при эквивалентном календарном дне возможен `blocked`.
3. Деньги, строки-числа, Markdown/HTML/код и другие формы сущностей покрыты **не полностью**. Нельзя обещать юридическую пригодность документа, не проверяя его специалистом.
4. Только отдельный CLI; исполнение **не автоматизировано сквозным процессом** создания текста. Интеграция в редакторский workflow — строго Issue #8.
5. `publish_ready=false` **во всех** результатах, в том числе `unchanged` и `review_required`. Нет обходящего блокировку флага; подтверждение в рамках человеческого процесса отдельно.
6. Хеш исходных байтов и количественные агрегаты могут быть чувствительными; логирование ввода отсутствует, пользовательские файлы в GitHub не загружаются.
