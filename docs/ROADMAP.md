# Дорожная карта публичного «СловоДела»

**Дата фиксации:** 2026-10-15. **Сфера:** только публичный Agent Skill в GitHub. Приватный MCP/API, n8n, VPS и `wirebot-lab` — **отложены**, не входят в эту очередь.

**Принятое решение:** [PROJECT_DECISIONS.md](PROJECT_DECISIONS.md) · **Техническая спецификация:** [PUBLIC_TECHNICAL_SPEC.md](PUBLIC_TECHNICAL_SPEC.md).

## Правило выполнения

> **Строго одна активная GitHub Issue за раз.** Созданные последующие задачи — план, а не разрешение работать параллельно. Каждый следующий этап заблокирован до подтверждения критериев и закрытия предшествующего. Не переходить «вперёд», даже если следующий этап кажется проще.

- **CURRENT: [#2](https://github.com/rubigotrafikcash-gif/slovodel/issues/2) — 01/10, контракт и методологические ограничения.** Только по этой задаче можно начинать работу после обсуждения.
- **BACKLOG: #3–#11.** Работа не начата, задачи открыты исключительно для планирования.
- Прямые изменения `main` для реализации запрещены: ветка → PR → проверки → merge → фактическая проверка → закрытие текущей Issue. После этого активировать следующую.
- Закрытие Issue означает выполненные acceptance criteria, а не наличие предложения, чата или черновика. Если этап заблокирован отсутствием лицензий/корпуса, оформить обоснованный `unavailable`/сохранить ограничение, не выдавать выдуманную функциональность.

## Определение завершения этапа (Definition of Done)

1. Работа выполнена только в объёме своей Issue; неожиданные расширения согласованы.
2. Код/справочники не менялись молча; опубликованы тесты по заявленным возможностям.
3. Утверждения о научной базе, историческом ПО и лицензиях ограничены доказательствами.
4. PR объединён и результат в `main` перепроверен (кроме задач, для которых PR объективно не нужен и это явно согласовано).
5. В Issue приведены PR/commit, тестовый результат, описание неустранённых ограничений.
6. Только теперь закрывается Issue и становится доступен следующий шаг.

## Режим обработки новой информации

Если во время шага N выявлен дефект другого шага, не бросать текущий процесс. Зафиксировать найденное как комментарий/дополнение к плану, оценить блокирующий риск и обсудить последовательность. Создать отдельную новую задачу только с разрешения; не открывать одновременно второй рабочий поток.

## Граница публичной версии

- **GitHub:** хранение исходников и запускаемые CI-проверки.
- **Среда пользователя:** исполнение Python там, где это доступно; без Python — только качественная редактура.
- **Не сейчас:** свой MCP, приватное REST API, сервер, n8n, Wirebot, Codex worker на домашнем компьютере, платные AI-провайдеры, постоянное хранилище чужих текстов.
