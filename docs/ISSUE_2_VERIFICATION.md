# Issue #2 — протокол документарной проверки

Дата: 2026-10-15. Область: только публичный навык, только инструкции/справочники/сценарии; без Python Core, серверов и приватной версии.

## Исходная проблема

В прежней версии `compliance.md` допускал оставлять неподтверждённую гарантию по настоянию автора, в то время как `evals/cases.md` №6 считала такой вывод нарушением. `SKILL.md` требовал «Готовый вариант» для любого запроса, в том числе для диагностического `audit`, не различал `compare` и `rewrite` и не определял формальное поведение при отсутствии Python.

## Решения по контракту

1. Разделены `audit`, `rewrite`, `create`, `compare`, `historical_research` с отдельными форматами выдачи.
2. Режим `audit` не переписывает текст; `compare` не выводит числовые дельты без подтверждённого измерения.
3. При отсутствующем Python Core нет имитации исполнения: только качественная редактура. `unavailable` = `null`, не 0.
4. Неподтверждённую гарантию не представлять как установленный факт в готовом к публикации тексте; исходник допускается цитировать отдельно «не подтверждено, не для публикации».
5. Для `rewrite` всегда есть краткое «Что изменено»; для `create` без исходника его нет.
6. Пустые обязательные исходники запрашиваются, а не подменяются предположениями. Прочтение вслух и запуск внешнего инструмента нельзя заявлять без фактического исполнения.
7. Сценарии ручных тестов сохранены и расширены с 17 до 25, недостающие входные данные в старых кейсах уточнены.

## Условия завершения

Проверить PR (файлы, отсутствие кода/скриптов и области приватного контура), отсутствие конфликтов, тестовую документацию. После merge перечитать `main`, указать итоговый commit/PR в Issue #2 и закрыть её. Следующую Issue не начинать без отдельного перехода.

Это именно запись о проверке документации: она не служит доказательством корректности математических вычислений, которые ещё не реализованы.
