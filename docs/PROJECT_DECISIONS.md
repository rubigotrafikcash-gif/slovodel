# СловоДел — принятые решения и границы проекта

Дата принятия решений: 2026-10-15. **Этот документ фиксирует границы проекта, а не текущий статус реализации.** Фактическое состояние задач проверяйте по [GitHub Issues](https://github.com/rubigotrafikcash-gif/slovodel/issues).

## 1. Текущее решение

**Сейчас разрабатываем только публичный AI-навык** в [rubigotrafikcash-gif/slovodel](https://github.com/rubigotrafikcash-gif/slovodel). Инструкции, тесты, исполняемые скрипты, открытые ресурсы и документация находятся в GitHub. Пользователь устанавливает навык из репозитория, а поддерживающий исполнение агент запускает локальные скрипты в *своём* доступном окружении.

Отдельная **приватная версия** (MCP/HTTPS API, VPS, n8n, личный worker, Codex/Claude как удалённые агенты, личные профили/история) **отложена**. Идея сохранена как возможное будущее направление, но **никакой работы, Issues, PR, инфраструктурных изменений или расходов по приватному контуру на этой стадии не инициировать**. Домашний `wirebot-lab`/AirBot и существующие VPN, Wirebot, Codex app-server, SSH, маршруты, DNS, VPS и n8n **не трогать**.

Не требуется реализовывать отдельный сервер для публичного навыка. GitHub предоставляет исходники и CI, но не обязан выполнять пользовательский анализ как постоянно работающий backend.

## 2. Цель публичного навыка

Открытый русскоязычный навык для:
- качественной редактуры с сохранением смысла, фактов, условий и голоса автора;
- проверяемого локального измерения доступных лингвистических показателей;
- сопоставления исходной и отредактированной редакций, прозрачного объяснения правок;
- использования в разных агентских средах, **если они поддерживают необходимые операции**.

**Оригинальная коммерческая программа «Словодел»/«Диатон» не предоставлена и не запускается**. Цель — независимая реализация документированной, проверяемой части исследовательской традиции; нельзя обещать численную эквивалентность историческому ПО.

Публичная версия не ограничивается постами: использовать существующую поддержку статей, рекламы, рассылок, сайтов, интерфейсов, сценариев и диалогов. Поддержка только русского языка — до отдельного решения.

## 3. Два компонента одного публичного навыка

1. **Python Core**: локальный детерминированный анализатор, без внешнего API, серверных запросов и платных ключей по умолчанию; сведения о методике, словарях, версиях и ограничениях сопровождают результаты. Скрипты распространяются *внутри* `skills/slovodel/`, чтобы инсталляция каталога навыка не теряла исполняемые файлы.
2. **AI-редактор**: текущий `SKILL.md`, правила для авторского голоса, различных форматов, фактов и результата. LLM не может объявлять собственную оценку математическим измерением и не может выдавать выдуманные проценты, «частоты мозга» и показатели «Диатона».

Механизм fallback: при отсутствии Python или разрешения на запуск скриптов допускается **только явно обозначенная качественная редактура** без псевдочисловых результатов. Необходимость одобрения перед изменением фактов и смысловых ограничений сохраняется.

## 4. Режимы

- `audit`: анализ, оригинал не изменяется;
- `rewrite`: текст изменяется только с защитой данных, объяснением правок и по возможности повторным анализом;
- `create`: новый текст из брифа, факты не придумывать;
- `compare`: сопоставление двух текстов одинаковыми вычислительными методами, явный отказ при несовместимости версий/корпусов;
- `historical_research`: описательная справка о первоисточниках без имитации недоступных расчётов.

Метрики делятся на `reproducible`, `qualitative`, `experimental`, `unavailable`. Число появляется только из проверяемого метода с достаточными входными данными. `unavailable` возвращается как `null`, никогда как 0. Экспериментальные реконструкции Журавлёва/Черепановой допустимы **только после отдельной проверки научных источников, таблиц и лицензий**.

## 5. Последовательная разработка — обязательное правило

**GitHub Issues — единый источник истины о выполнении.** Задачи создаются заранее в порядке зависимости, но **активна строго одна**. Все остальные — очередь `backlog` и не исполняются, пока текущая задача не закрыта по её критериям приёмки.

Порядок работы:
1. Открыть **первую незавершённую** Issue из [плана](ROADMAP.md); проверить входные условия.
2. Работать **только по ней**. До изменения кода/документации обсуждать спорные решения, если их нет в спецификации. Для реализации — отдельная ветка/PR (не прямой push в `main`), необходимые тесты.
3. Проверить критерии, подтвердить работоспособность, сверить фактические файлы и состояние GitHub.
4. Закрыть Issue **только после** выполнения критериев и связанного merge; отметить конкретные ссылки на PR, коммит и результаты тестирования.
5. **Только затем** переводить следующую Issue из очереди в активную. Не параллелить PR или работу над разными этапами без нового явного решения пользователя.

Исключения (безопасность/блокер) обсуждать и фиксировать отдельно; не перескакивать молча. Не закрывать задачи лишь на основании текста отчёта.

## 6. Защита проекта и распространение

- Не изменять существующие сервисы, VPS, Wirebot и домашний сервер.
- Не использовать закрытые таблицы/чужие материалы без проверки прав; не включать неизвестно лицензированные корпуса в MIT-репозиторий.
- Не передавать пользовательские тексты на сторонние сервисы по умолчанию; никаких токенов в GitHub.
- Не менять факты, имена, отрицания, сроки, ссылки, деньги без согласования.
- Не выдавать качественные суждения за измерения и не обещать контролируемое внушение или доказанное влияние на конверсию.
- Установка публичного навыка должна оставаться возможной **без Python** для текстового режима; вычислительные функции требуют разрешённого локального запуска.
