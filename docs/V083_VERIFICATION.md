# Кандидат 0.8.3: модальность и единая проверка свидетельств

30 октября 2026. Issue #33. Опубликованный тег/архив 0.8.2 не заменяется.
Core 0.8.3, A8 rules 2.5. Новый выпуск ещё не опубликован.

## Доработка после 20 новых материалов

Добавлен `check_workflow.py`: фактический запуск Core, запись его кода завершения,
проверка исходного JSON единым помощником и проверка заданного объёма ответа.
Коды: 0 — свидетельство проверено, 5 — Core blocked, 6 — ошибка проверки,
7 — нарушение объёма; исходный код Core всегда хранится отдельно. Ни один статус
не является разрешением публикации. Модель и effort без внешних метаданных — null.

A8 2.5 нормализует только типографику числового диапазона, эквивалентную запись
часов в сутки и регистр известных самостоятельных заголовков научной статьи.
Идентификаторы, URL, буквальные защищённые фразы и ISO-даты сохраняют защиту.
Изменение «менее»/«более» при числовой величине теперь даёт блокировку.

В инструкциях уточнены границы create/rewrite и исключения для одной короткой
строки; добавлены сверка смысла локального совета в audit и наличие выбранного
продавца в карточке. Три синтетических редакторских сценария сохранены в
`evals/v083-followup.json`; полные чужие тексты в репозиторий не включены.

Локальная проверка: 292 теста, 288 прошли, четыре пропущены; покрытие выбранных
12 модулей — 96%, нового исполнителя — 100% строк. Проверка переносимости
каталога и валидация навыка пройдены. Результаты повторных модельных сеансов
фиксируются отдельно после заморозки пакета.

## Исправление Core

Модальность сопоставляется с действием в ограниченной локальной клаузе,
а не по общим суммам слов «может»/«должен» во всём тексте. Учтены прошедшие
формы возможности. Для известных форм потеря ограничителя и реальный переход
may/must дают blocker; неоднозначное соответствие остаётся review.

Ограничения: это лексическая эвристика, не синтаксический или семантический
парсер. Неизвестные глагольные формы, более 64 кандидатов и длинные клаузы
обрабатываются консервативно. Агент обязан завершать смысловую сверку.

## Единый помощник

`skills/slovodel/scripts/verify_workflow.py` проверяет существующий JSON Core,
исполнение, текущие версии, реальные входные SHA-256, соответствие кода завершения
решению и контекстный файл. Он не изменяет отчёт и не разрешает публикацию.

Структурные проверки работают на стандартной библиотеке. Полная Draft 2020-12
проверка необязательна и выполняется при установленном `jsonschema`; без него
возвращается `schema_validation=unavailable`. Флаг `--require-schema` в этом
случае завершается ошибкой 6. Самописный частичный валидатор не выдаётся за полный.

## Те же четыре задания в новых сеансах Codex

Локальный кандидат установлен штатным механизмом плагинов. 52 файла навыка
побайтно совпадают с кандидатом. TASK.md и исходники каждого задания совпадают
с предыдущей проверкой 0.8.2. Четыре новых сеанса Codex CLI: gpt-6.1-sol,
effort medium, по одному запуску на режим. Точный серверный снимок модели
независимо не засвидетельствован. Вызов явный, с путём установленного кандидата;
тело навыка не вставлялось в задание. Старая версия отключена только для этих
CLI-вызовов. Аккаунтный плагин не обновлялся.

| Режим | Итог |
|---|---|
| create | Бриф сохранён, новые условия не придуманы; Core draft_requires_review. |
| rewrite | Дата, историческое время, модальность, атрибуция и цена сохранены; Core draft_requires_review вместо прежней ложной блокировки. |
| audit | Реальная ошибка согласования найдена; допустимая конструкция не объявлена ошибкой; Core audit_only. |
| compare | Верно обнаружены «от» → «до» и выдуманная гарантия; Core comparison_only. |

Каждый сеанс использовал общий помощник и сам завершил смысловую сверку.
В рабочем интерпретаторе `jsonschema` отсутствует; все четыре честно сохранили
unavailable. Затем тем же помощником с существующими локальными зависимостями
выполнены полные проверки 14 экземпляров схем, без изменения исходных отчётов.
Самописных валидаторов в четырёх новых сеансах нет.

Чтобы отделить исправление Core от новой редактуры модели, дополнительно
повторён **неизменённый прежний итоговый текст** rewrite: 0.8.2 blocked →
0.8.3 draft_requires_review. Остальные три старых ответа сохранили решения.

Восемь прежних диагностических пар повторены без изменения входов:

- Два разных действия («могут открыть» и «нужно написать»): ложный blocker снят.
- «Могли открыть» → «открыли» и «могут открыть» → «открыли»: теперь blocked.
- Историческая возможность и перефразирование канала записи: остаются review.
- Подмена года, отрицания и нижней границы оплаты: по-прежнему blocked.

## Что ещё не подтверждено

Четыре синтетических примера не оценивают общую надёжность или превосходство
генерации. Оценка содержания выполнена агентом, без слепого отдельного оценщика.
Нужны свежий контроль качества с одинаковыми моделью/effort и проверка неявного
подключения навыка. ChatGPT/Claude и интерфейс Desktop отдельно не проверялись.
Короткий create всё ещё содержит необязательные пояснения; это стилевое замечание,
не ошибка фактов. Внутренний журнал rewrite назвал нормализацию букв
фонологическим приёмом — это орфографическая операция; измерений звучания не было.

Полные тексты, ответы и журналы локальны. Этот документ не подтверждает merge,
новый GitHub release или обновление аккаунтного плагина.
